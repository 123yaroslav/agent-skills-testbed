# Стенд для тестирования навыков LLM-агентов

[![CI](https://github.com/123yaroslav/agent-skills-testbed/actions/workflows/ci.yml/badge.svg)](https://github.com/123yaroslav/agent-skills-testbed/actions/workflows/ci.yml)

Стенд проверяет навыки (Agent Skills) LLM-агентов на задачах с документами и данными. Он прогоняет агента на сценариях с навыком и без него, проверяет результат и действия, считает стоимость и время. По итогам видно, помогает ли навык, выбирает ли агент нужный навык из библиотеки, почему прогон провалился и не стало ли хуже после обновления навыка, модели или агента.

Проект курса ML System Design, ИТМО, 2026.

## Зачем

Навыки пишут обычным текстом и почти не тестируют. В SkillsBench навыки от экспертов подняли долю решенных задач с 33,9% до 50,5%, а навыки, которые модель написала себе сама, в том же эксперименте ее опустили. Эффект одного и того же навыка меняется от модели к модели. Подробности и источники в [дизайн-документе](docs/ml_system_design_doc.md).

## Статус

Итерация 1. Настроен репозиторий, написан дизайн-документ. Из кода пока есть модуль статистики и скрипт, который оценивает разброс исходов по опубликованным результатам SkillsBench. Оба нужны для расчетов в дизайн-документе.

## Быстрый старт

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync                                   # зависимости из uv.lock
uv run pre-commit install                 # хуки перед каждым коммитом
uv run pre-commit run --all-files         # ruff, mypy, gitleaks и базовые проверки
uv run pytest                             # тесты
uv run python -m skills_testbed.power     # таблица чувствительности из дизайн-документа
```

## Структура

| Путь | Что там |
|---|---|
| `docs/ml_system_design_doc.md` | Дизайн-документ |
| `src/skills_testbed/` | Код стенда |
| `scripts/skillsbench_variance.py` | Оценка разброса исходов и прироста от навыков по данным SkillsBench |
| `tests/` | Тесты |
| `pyproject.toml` | Зависимости и настройки ruff, mypy, pytest |
| `.pre-commit-config.yaml` | Хуки перед коммитом |
| `.github/workflows/ci.yml` | Те же проверки и тесты в CI |

## Инструменты

| Инструмент | Зачем |
|---|---|
| uv | Зависимости и окружение, версии зафиксированы в `uv.lock` |
| ruff | Линтер и форматер. Правила pycodestyle, pyflakes, isort, bugbear, bandit и другие, список в `pyproject.toml` |
| mypy | Проверка типов в строгом режиме |
| gitleaks | Не дает закоммитить ключ API. Проект работает с ключами LLM-провайдеров |
| pre-commit | Запускает все проверки перед коммитом |
| GitHub Actions | Повторяет проверки и тесты на каждый PR |

## Как ведем репозиторий

Каждое домашнее задание делаем в ветке `hw_N` и вливаем в `main` через PR после ревью ментора и двух студентов. Коммиты маленькие, по одному изменению. Правила в [CONTRIBUTING.md](CONTRIBUTING.md).
